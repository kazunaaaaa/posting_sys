# ポスティング配布エリア選択システム

ラクスルの「地図から簡単注文」のように、**地図上でポスティング配布エリアを選び、配布部数を自動算出**するWebアプリのMVPです。カート/注文機能は持たず、**配布部数の算出とAIによる最適エリア分析に特化**しています。

- 🗾 **全国自治体対応** … 47都道府県・全1,916市区町村から選択。境界ポリゴンはオンデマンド取得＋キャッシュ
- 📍 **中心地のピン** … 住所・店舗名で検索するとピンを立てて地図を移動。「📍を地図の中心に移動」やドラッグでも動かせる
- 🧮 **部数で選ぶ（📍から約10,000部を追加）** … ピンに近い町丁目から順に、目標部数に最も近くなるまで自動選択。ピン周辺の市区町村は**県境をまたいで自動で読み込む**（例: 大和市の南林間 → 相模原市南区・町田市・座間市）
- 🤖 **AIで最適エリアを作成** … 選択中のエリアに限らず、ピン周辺から目標部数（例: 10,000部）に最も近い「まとまったエリア」を自動作成。
  **ターゲットの多い町丁目を優先**し、**川・高速道路・国道・線路をまたぐ町丁目は後回し**（大きな川は町丁目の水面区画で隔てられるため越えない）。飛び地は作らず、除外した理由も表示
- 👥 **ターゲット分析** … 業態ごとの標準ターゲット（例: 美容室=20〜59歳の女性、学習塾=6〜15歳）または任意の年齢・性別で、
  町丁目ごとのターゲット人数を国勢調査の男女・年齢別人口から計算。AI分析で「ターゲットが多いエリア」を表示
- 🎯 **円で範囲選択（Raksul仕様）** … 半径(km)を指定して「円を追加」→ ピンを中心に円内のエリアを一括選択。複数円OK（Google Mapsでは円の移動・半径変更も可）
- 📥 **配布部数表（エリア表）ダウンロード** … 市区町村名・町丁目名・世帯数・配布予定数（`=ROUNDDOWN(世帯数×カバー率,-1)`）と、選択エリア・円・ピンを描いた地図をExcelに出力（Googleスプレッドシートでもそのまま開ける）
- 🏘️ **町丁目配布（実境界）** … 全国どの市区町村でも、国勢調査の**実際の町丁目境界**を読み込んで町丁目ごとに選択。世帯数も町丁目単位の実数（令和2年国勢調査）
- 📮 **配布部数の自動算出** … 各エリアの世帯数（国勢調査／住民基本台帳）× **世帯カバー率（既定70%）** を **10部単位で切り捨て**（配布部数表の `ROUNDDOWN(…,-1)` と同じ）。
  カバー率は左パネル「配布サマリ」の **世帯カバー率(%)** に数値で入力して変更でき（1〜100%）、画面の部数・📍から○部の追加・🤖 AI最適エリア・AI分析・Excel（F1のカバー率）すべてに反映されます。「70%に戻す」で既定値に戻ります。
- 🔍 **競合分析** … 業態を選ぶと、その業態の競合が地図上にプロットされる
- 🤖 **AIによる最適エリア分析** … 世帯規模・競合密度・配布効率・コストをスコア化し、最適エリアをAIが提案・解説
- 🚚 **配布会社の原価・見積** … 選択エリアの各配布会社の原価/見積単価を集計（実データを徐々にプロットしていく土台）

## Macでのかんたん起動（おすすめ）
ターミナルに次の1行を貼り付けて実行すると、デスクトップに「ポスティング起動」ができ、そのまま起動します（初回のみ）。
```bash
curl -fsSL https://raw.githubusercontent.com/kazunaaaaa/posting_sys/claude/posting-area-distribution-s7c07d/start-mac.command -o ~/Desktop/ポスティング起動.command && chmod +x ~/Desktop/ポスティング起動.command && open ~/Desktop/ポスティング起動.command
```
以降は **デスクトップの「ポスティング起動」をダブルクリック** するだけで、次を自動で行います（`start-mac.command`）。
1. 最新のコードをGitHubから取得して `~/posting-sys` に配置（`.env`・インストール済みの部品・取得済みデータは残す）
2. 部品のインストール
3. 町丁目データの事前取得（既定は一都三県。取得済みはスキップ）
4. アプリを起動して http://localhost:4000 をブラウザで開く（止めるときは Ctrl + C）

全国のデータを取得したいときは、一度だけ `PREFETCH_AREA=全国 bash ~/Desktop/ポスティング起動.command` を実行します。

**Macログイン時に自動で起動する**（一度だけ実行）:
```bash
bash ~/Desktop/ポスティング起動.command --install-autostart     # 登録（ブラウザも自動で開く。開かない場合は --no-browser を付ける）
bash ~/Desktop/ポスティング起動.command --status                # 状態の確認
bash ~/Desktop/ポスティング起動.command --uninstall-autostart   # 解除
```
- ログイン時に、最新コードの取得 → 起動 → ブラウザ表示を自動で行い、町丁目データの事前取得は裏で進めます。落ちた場合は自動で再起動します。
- アプリ本体は `~/posting-sys` に置きます（自動起動のプログラムはmacOSの保護によりデスクトップを読めないことがあるため）。`.env` はデスクトップの旧フォルダから自動で引き継ぎます。
- ログ: `~/Library/Logs/posting-sys.log`（事前取得は `posting-sys-prefetch.log`）

## クイックスタート

```bash
npm run install:all          # ルート / server / client の依存をインストール
npm run dev                  # server:4000, client:5173（→ http://localhost:5173）

# 本番ビルド＋単一サーバー起動（http://localhost:4000）
npm run build && npm start
```

町丁目モードは、市区町村を選ぶと **e-Statから町丁目境界と世帯数を自動ダウンロード**します（初回のみ数秒、以降はキャッシュ）。e-Statへ接続できる環境で実行してください。

## データの実データ性と充填元

| データ | この状態での挙動 | 実データ源（実運用） |
|--------|------------------|----------------------|
| 全国市区町村マスタ（コード・名称・重心） | ✅ 実データ同梱（1,916件） | [localgovjp](https://github.com/code4fukui/localgovjp) |
| 市区町村の**世帯数** | ⚠️ 未接続時は `null`（部数は「—」表示）。**捏造値は入れていません** | **e-Stat API**（国勢調査／住基）|
| 市区町村の**境界ポリゴン** | ✅ 選択時にオンデマンド取得＋キャッシュ | **e-Stat 統計GIS 境界データ**（推奨）／[niiyz/JapanCityGeoJson](https://github.com/niiyz/JapanCityGeoJson)（キー不要フォールバック）|
| 町丁目の境界・世帯数 | ✅ 選択した市区町村ぶんを自動取得＋キャッシュ | e-Stat 境界データ（令和2年国勢調査 小地域）|
| 競合POI | ✅ サンプル生成／実POI取得 | Google Places API →（キー無ければ）OpenStreetMap Overpass |
| 配布会社 原価・見積 | ✅ サンプル同梱 | 各社と連携して蓄積（`server/data/pricing.sample.json`）|

> **世帯数について**: 「配布部数＝最新世帯数×70%」の**世帯数の正データはe-Stat**です。本リポジトリのビルド環境ではe-Statへ到達できないため、市区町村の世帯数は未接続時 `null`（誤った推計値は表示しない方針）。`ESTAT_APP_ID` を設定すると全国の部数が真値で算出されます。町丁目の世帯数は、e-Stat境界データに含まれる町丁目別の実世帯数（SETAI）を使います（APIキー不要）。

### e-Stat（世帯数）の接続手順と疎通確認
1. [e-Stat API](https://www.e-stat.go.jp/api/) でアプリケーションID(appId)を取得し `.env` の `ESTAT_APP_ID` に設定
2. **疎通確認スクリプトを実行**（statsDataId未設定なら候補を検索表示）:
   ```bash
   npm --prefix server run estat:check
   ```
3. 表示された候補から市区町村別世帯数の表を選び `ESTAT_STATS_DATA_ID` に設定して再実行。
   スクリプトが「接続 → メタ検出（世帯数分類の自動判定）→ 世帯数取得 → 全国マスタとの結合率」を検証し、
   松戸市などサンプル自治体の `世帯数 → 配布部数(×70%)` とPASS/FAILを表示します。
4. PASSしたら `server` を再起動すると、市区町村モードで**真値の配布部数**が表示されます。
5. 自動検出が合わない表では `ESTAT_HOUSEHOLD_CLASS` / `ESTAT_HOUSEHOLD_CODE` / `ESTAT_TIME_CODE` で明示できます。

> 実装は `server/services/estatClient.js`（getStatsList/getMetaInfo/getStatsData）。世帯数分類の検出・
> `@area`→市区町村コードの結合・全国/都道府県の除外・最新年フィルタを行います。パースは
> `npm --prefix server test`（`server/test/estatClient.test.mjs`, モック16項目）で検証済み。
### 配布部数表（エリア表）Excel
- 右パネル「📥 配布部数表」で店舗名・案件名を入れて「配布部数表ダウンロード（Excel）」を押すと、
  `【エリア表】_<店舗名>様_<案件名>_<部数>部エリア.xlsx` を出力します（シート名は「3万部エリア」など）。
- 列: 市区町村名 / 町丁目名（例: 南林間一丁目 → 南林間(1)）/ 世帯数 / 配布予定数（=ROUNDDOWN(世帯数×$F$1,-1)）/ 備考。F1 にカバー率、F2 に合計部数。
- G4 から右側に地図画像（選択エリア・町名ラベル・赤い円と半径・ピンと店名・**競合店舗（紫の点）**・凡例）を貼り付けます。
- ターゲット（業態の標準、または入力した年齢・性別）がある場合は、合計部数の下に **ターゲット人数** と **ターゲット占有率（人口に占める割合）** の2行を追加します（見出し以降は2行下がります）。
- 「📍から約○部を追加」「🤖 AIで最適エリアを作成」で選んだときも、ピンを中心に、最も遠い町丁目の中心までの半径の **赤い円** を描きます（円の一覧に「AI」「○部」と表示）。
  この円を動かしたり大きさを変えたりすると、通常の円と同じく範囲内の町丁目を選択します。
- 地図の背景には **Maps Static API** を使います。Google Cloud で「Maps Static API」を有効にし、APIキーの「APIの制限」にも追加してください。
  未設定でも、背景なし（エリア・円・ピンのみ）の地図で出力できます。
- Googleスプレッドシートで使う場合は、ダウンロードしたファイルをGoogleドライブにアップロードして開いてください（式も保持されます）。

### 顧客データ（CSV）の取り込み
- 左パネル「👥 顧客データ（CSV）」で会員・顧客のCSV（UTF-8 / Shift_JIS）を読み込むと、住所を町丁目に照合して、地図に**町丁目ごとの顧客数**を緑のバブルで表示します。
- **個人情報の扱い**: ファイルはこのMacのブラウザ内で読み、サーバー（同じMac）には行番号・都道府県・住所だけを送ります。氏名・電話番号・生年月日は送らず、どこにも保存しません（画面を閉じると消えます）。住所の位置はGoogle等の外部サービスを使わず、町丁目データとの照合だけで求めます。
- 列は見出しで判定します（「都道府県」「住所」または「住所1〜3」「市区町村」、任意で「年齢」「生年月日」「性別」「退会日」「店舗名」）。
- 住所の表記ゆれ（全角数字・「－」「ー」・「1丁目23番6号」・政令市の区の有無・郡名・ケ/ヶ）を吸収します。丁目が書かれていない住所は、その町の丁目に均等に割り振ります。
- 表示する内容: 対応できた人数、対応できなかった行、📍からの距離（顧客の50/80/90%が何km以内か・その半径の円）、顧客の年齢層（ターゲットに設定可）、顧客が多い町丁目（1000世帯あたり）。
- 「AI分析・AI最適エリア作成に使う」をオンにすると、総合スコアに **顧客実績（25%）** を加え、🤖 AI最適エリア作成でも世帯あたりの顧客が多い町丁目とその周辺を優先します。AIの解説・Excelの「AI分析レポート」にも顧客の多いエリアを載せます。
- 配布部数表の地図に顧客の分布を入れるかは選べます（初期はオフ。配布会社に渡す場合などに配慮）。
- 顧客データを読み込んでいると、配布部数表に別シート **「顧客分析レポート」** を付けます（オフにも可）。内容: 結論（商圏・顧客の多い／浸透している町丁目・年齢層・絞り込んだ配布エリアの顧客数と浸透度・追加候補）、取り込んだ顧客データ、📍からの距離別の顧客、年齢層、市区町村別、顧客が多い町丁目（上位20）、配布エリアの町丁目ごとの顧客、追加候補、分析方法。個人の情報は含めず集計だけを載せます。

### エリア表の貼り付け（Excel → 地図に反映）
- 左パネル「📋 エリア表を貼り付けて反映」に、Excel・スプレッドシートでコピーした表（都道府県・市区町村・町丁目名・世帯数・配布予定数）を貼り付けて「地図に反映」を押すと、該当する町丁目を地図で選択します。反映後もクリック・円で追加／解除して調整できます。
- 列の順番は自由です（見出し行があれば見出しで判定。都道府県・世帯数・配布予定数の列は無くても可。当アプリの配布部数表の形式もそのまま使えます）。
- 町丁目名の表記ゆれ（「泉町二丁目」「泉町２丁目」「泉町(2)」、「大字」の有無、「ケ/ヶ」「の/ノ」など）は自動で吸収します。丁目のない町名（「泉町」）は、他の行で指定していない丁目に対応させます。
- 「貼り付けた世帯数を使う」をオンにすると、1行が1町丁目に対応した行は、貼り付けた世帯数で配布部数・エリア表を計算します。
- 表の上に住所だけの行（例「坂戸市北峰183-2」）があれば、その場所に📍ピンを立てます（Google Maps接続時）。
- 照合できなかった行は一覧で表示します。地図でクリックして追加してください。

### 顧客データで前回の配布エリアを見直す（傾向・削除/追加の根拠）
- 前回の配布エリアを「比較元」として記録します。エリア表を貼り付けると自動で記録されます（「この表を前回の配布エリアとして記録」）。地図で選んだエリアは「今の選択を記録」で記録できます。
- 顧客データ（CSV）を読み込み、📍を立てて **🔁 顧客データで前回エリアを見直す** を押すと、部数をほぼ変えずにエリアを組み替えます。
  - 削除: 前回配布したのに顧客0人で、前回エリアの平均の浸透度（1000世帯あたりの顧客数）なら0.8人以上いるはずの町丁目のうち、隣接する前回エリアを含めた周辺の浸透度も平均の6割未満のもの。まとめて「偶然0人になる確率」（ポアソン分布）が10%未満のときだけ削除します（前回の部数の35%まで）。
  - 追加: 未配布なのに顧客がいて、浸透度が前回エリア平均の5割以上、かつ残したエリアに隣接する町丁目を、浸透度の高い順に、削除で浮いた部数の範囲で追加します。
- 配布部数表（Excel）には、顧客データがあるときは必ずシート **「顧客分析レポート」** を付け、次を載せます。
  - 顧客分布の傾向（前回エリア内の顧客の割合・距離帯別／方位別の浸透度・顧客0人の町丁目の偏り・エリア外の顧客）
  - 配布エリアの見直し（前回 → 今回）: 削除・追加した町丁目ごとの数値と根拠の文章。前回エリアのまま出力したときは見直し案を載せます。
- 地図画像には、前回から外した町丁目を灰色の破線で描き、顧客の90%が入る範囲まで表示を広げます。エリア表の備考には「追加（前回エリア外）」と入ります。
- 「AI分析レポート」シートには配布会社の見積を載せません。

### AI最適エリアとターゲット人数
- 「📍から約○部」を選んで **🤖 AIで最適エリアを作成** を押すと、ピンのある町丁目から隣り合う町丁目へ順に広げて、目標部数に最も近いエリアを作ります。
  優先度 = 距離 ×（1＋分断の度合い）÷ ターゲット密度。分断の度合いは、ピンから町丁目までに川(3)・高速道路(2.5)・国道(1.5)・線路(1.5)・主要地方道(0.6)を何本またぐか。
- 川・道路・線路は OpenStreetMap（Overpass API）から取得してキャッシュします（`OVERPASS_URL` で取得先を変更可）。取得できないときは、町丁目の水面区画による川の分断だけを考慮します。
- ターゲット人数は e-Stat の国勢調査 小地域「男女・年齢(5歳階級)別人口」から計算します（`ESTAT_APP_ID` が必要。市区町村ごとにキャッシュ）。
  取得できない町丁目は、町丁目の人口を全国の年齢構成で按分した**推計**になり、画面に「推計」と表示します。
- 取得の確認: `npm --prefix server run demographics:check -- 13122`（葛飾区の例。統計表の検索 → 町丁目との対応 → 人口の照合 → PASS/FAIL）

### 所得（平均所得・所得指数）
- **市区町村の平均所得（実データ）**: e-Stat「社会・人口統計体系」の 課税対象所得 ÷ 納税義務者数 ＝ 納税者1人あたり平均所得。世帯年収ではありません。
- **町丁目の所得指数（推計）**: 町丁目の所得の統計は公開されていないため、国勢調査 小地域の
  管理職・専門職の割合(40%)・持ち家率(30%)・夫婦と子どもの世帯の割合(20%)・単身世帯の割合(10%、多いほど下げる)から、
  市区町村内での相対的な高さを 0.6〜1.6（平均=1.00）で推計し、「高い／やや高い／平均／やや低い／低い」で表示します。金額は出しません。
- ターゲット属性の **所得層（指定なし／高め／低め）** を選ぶと、AI分析のスコア（所得層15%）と 🤖 AI最適エリアの作成（所得指数の高い/低い町丁目を優先）に反映します。
- 取得結果は `~/.posting-sys/towns/income/` にキャッシュします。確認: `npm --prefix server run income:check -- 14213`（大和市の例）

### Excel の「AI分析レポート」シート
- 配布部数表をダウンロードすると、エリア表とは別のシート **「AI分析レポート」** に、分析条件（業態・ターゲット・所得層・目標部数・中心地）、
  サマリー、AIによる分析文、AI最適エリアの作り方（分断で除外した町丁目など）、ターゲットが多いエリア、所得指数の順位、エリア別スコア、配布会社の見積、データの出典を記載します。
- AI分析をしていない、または選択を変えた後にダウンロードした場合は、自動でAI分析を実行してからレポートを作ります。

### 町丁目データの一括事前取得（一都三県・全国）
初回だけまとめて取得しておくと、どの地域を検索してもすぐに町丁目が表示されます。
```bash
npm --prefix server run towns:prefetch -- 一都三県      # 251市区町村・約3〜5分
npm --prefix server run towns:prefetch -- 全国          # 1,896市区町村・約30〜40分
npm --prefix server run towns:prefetch -- 東京 神奈川    # 都道府県名やコード(13)でも指定可
```
- 取得済みはスキップするので、途中で止めても（Ctrl+C）同じコマンドで続きから再開できます。失敗した分も再実行で取り直します。
- オプション: `--dry-run`（対象件数と見込み時間だけ表示）、`--concurrency=3`（同時取得数・最大5）、`--force`（取り直し）、`--only=14213,14153`（指定コードのみ）
- 保存先は **`~/.posting-sys/towns`**（環境変数 `TOWN_CACHE_DIR` で変更可）。プロジェクトの外にあるので、コードを更新・入れ替えてもデータは残ります。
- 保存容量の目安は一都三県で数十MB、全国で数百MBです（実際の値は取得後に表示されます）。

### 町丁目データ（e-Stat 境界データ）
- 町丁目モードで市区町村を「＋読込」すると、サーバーが e-Stat から **令和2年国勢調査 小地域（町丁・字等別）** の境界データ（シェープファイル）をダウンロードし、
  町丁目ごとの **実境界ポリゴン・世帯数(SETAI)・人口(JINKO)** に変換して `~/.posting-sys/towns/<市区町村コード>.json` にキャッシュします。
- 事前取得・動作確認: `npm --prefix server run towns:fetch -- 12207`（複数コード可）
- e-Statへ接続できない環境では、[e-Stat 境界データ](https://www.e-stat.go.jp/gis/statmap-search?type=2)から
  「国勢調査 → 2020年 → 小地域（町丁・字等別）→ 世界測地系緯度経度・Shapefile」を市区町村単位でダウンロードし、
  `~/.posting-sys/towns/raw/<市区町村コード>.zip` に置けば読み込まれます。
- 分割された町丁目は1区画に統合（世帯数は重複計上しない）、水面調査区は除外します。

## スコアリングの考え方（`server/services/scoring.js`）

| 軸 | 指標 | 重み |
|----|------|------|
| 到達 (reach) | 世帯数（配布到達数） | 35% |
| 競合機会 (opportunity) | 世帯数 ÷ (競合数+1) | 30% |
| 配布効率 (efficiency) | 世帯密度 | 20% |
| コスト効率 (cost) | 到達世帯 ÷ 配布コスト（配布会社の最安見積単価を反映） | 15% |

各軸を0–100に正規化し重み付け。世帯数が未取得のエリアは対象外（`skipped`）として明示します。`ANTHROPIC_API_KEY` を設定するとClaudeが最適エリアの理由・優先度・予算配分を日本語で解説します。
